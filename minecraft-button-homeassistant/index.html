 I Wired a Minecraft Button to My Bedroom Light (No Cheats, No Mods)

What if pressing a button in Minecraft turned on a light in my actual bedroom?

Not “flip a virtual switch that looks like a light.” An actual, physical, Zigbee bulb, plugged into the wall of the room I sleep in. Pressed in Minecraft, lit in real life.

Skip this paragraph if you’re not informed in Minecraft specifics

The constraint I gave myself made it sound impossible: no cheats. No command blocks, no /give, no flipping “Allow Cheats” on. It had to work in a boring, legit, survival-rules singleplayer world - the kind you’d actually play in, not a creative sandbox rigged up for a demo.

Turns out there’s a loophole. This post is about finding it, architecting around it, and the very dumb bugs that showed up along the way.

The constraint (and the insight that cracks it open)

If you’ve messed with Minecraft command blocks before, you know the usual toolkit: command blocks, /execute, /give - is all gated behind “Allow Cheats” (they call them commands nowadays :) ) Turn cheats off, and none of that works. Case closed, right?

Here’s the loophole: datapacks are not commands.

A datapack’s functions run automatically as part of the game loop. On world load, and could be loaded on a tick tag every single tick. Regardless of whether cheats are enabled. The cheats toggle only gates commands typed by a player or admins explicitly into chat (using /) or command blocks. It says nothing about what the game itself decides to execute as part of its normal tick cycle. Datapacks are data, not player input, so they slip right past the restriction.

That’s the whole trick. Everything else is built on top of that one fact.

The architecture

At a high level, the flow looks like this:

[Button in-game]
        │  (in-game pulse (redostone))
        ▼
[Datapack: checks exact coordinates(button) state every tick]
        │  (rising edge detected)
        ▼
[/say <marker string>]   --->  written into latest.log
        │
        ▼
[External script tails latest.log]
        │  (regex match on marker string)
        ▼
[HTTP POST ---> Home Assistant webhook]
        │
        ▼
[Real device toggles ---> e.g. a Zigbee smart light]

The datapack side polls the button’s block state every tick using execute if block ~ ~ ~ #minecraft:buttons[powered=true], compares it against a stored value to detect a rising edge (unpowered —> powered), and when it sees one, fires:

# functions/check_button.mcfunction
# runs every tick via #minecraft:tick

execute if block ~ ~ ~ #minecraft:buttons[powered=true] run scoreboard players set button_state bridge 1
execute if block ~ ~ ~ #minecraft:buttons[powered=false] run scoreboard players set button_state bridge 0

execute if score button_state bridge matches 1 unless score button_state_prev bridge matches 1 run say MC_HA_BRIDGE:BUTTON_PRESSED

scoreboard players operation button_state_prev bridge = button_state bridge

/say is the hero here. It’s a completely unprivileged command (no cheats needed to broadcast a message to chat). Read more on /say, and every chat message gets timestamped straight into .minecraft/logs/latest.log. So instead of trying to get data out of Minecraft through some code or request, I just print it, and read the log file. Read more on Minecraft’s file structure

On the background, a small Python script continuously monitors latest.log and when it matches MC_HA_BRIDGE:BUTTON_PRESSED, it sends a POST request to a Home Assistant webhook, which triggers an automation, in my case, toggling a Zigbee2MQTT-connected light bulb through Home Assistant.

Why not something simpler?

A couple of “obvious” alternatives are:

“Just use RCON“: RCON is how a lot of Minecraft <—> external-world integrations normally work but RCON is a server feature. Singleplayer worlds don’t run an RCON listener at all, cheats or no cheats. To get RCON you’d need to convert your world into a server, which defeats the entire point of “a normal singleplayer world I would actually play in”.

Modding: This is a good alternative and would mean dodging the external script. I have vibe coded one in the past and it works great but I am not sure about how different modloaders deal with HTTP requests.

What’s next

Right now it’s one-directional (Minecraft —> real world), the obvious next step is closing the loop: Home Assistant state changes writing back into the world via a /data, so a real-life motion sensor could, say, light up a lamp in-game. There’s also room to generalize the “log line as event bus” pattern beyond Redstone. inventory changes, achievement triggers, death events, whatever a datapack can observe.

This is a genuinely fun weekend project, and I’d love to see what other people build with it.
